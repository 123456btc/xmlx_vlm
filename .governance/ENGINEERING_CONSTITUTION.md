# Engineering Constitution — 核心工程宪法 (32 条非妥协红线)

> **生产实施说明**：本宪法适用于 `xmlx_vlm` 核心架构、AI Trader 引擎、OMS 订单风控与 Agent Core。所有规则由 `.governance/scripts/ci_gate.py` 自动化门禁实施静态拦截。

---

## 32 条不可逾越的非妥协红线 (Non-negotiable Rules)

### 1. 交易与 OMS 网关铁律
1. **订单唯一 SSOT 登记**：严禁任何策略、AI 或第三方 Agent 绕过 OMS 直接调用交易所底层下单 API。所有订单必须经由统一 OMS Tracker 登记，并强制通过前置微秒级风控计算。唯一例外是一键风控 Panic 急停平仓指令。
2. **禁止静默忽略订单拒单**：所有 `on_rejected` / `on_failed` 回调必须明确区分是瞬态错误（超时、限频）还是致命错误（资金不足、权限缺失），严禁只打一行 log 便静默返回。
3. **订单结构必须包含 Correlation ID**：所有订单提交与撤单请求必须携带链路追踪的唯一相关性标识（`correlation_id` / `client_oid`），确保跨异步协程和重放审计时不丢单。
4. **市价单必须附带参考价格估算 (Price Hint)**：严禁提交名义价值为 0 的盲目市价单；必须传入最新盘口买一/卖一或标记价以精确测算保证金与最大回撤影响。

### 2. 金融精度与数值确定性
5. **严禁原生浮点数计算资金**：资产余额、保证金、持仓成本及盈亏计算，严禁使用原生 `float / f64`，冷路径必须统一使用 `Decimal` / 高精度定点数。
6. **清仓判断必须引入 Epsilon 容差**：浮点或定点计算多笔撮合后易残留微小碎屑（如 `4.33e-19`），仓位归零与均价重置必须使用 epsilon 容差（如 `abs(pos) < Decimal("1e-9")`）。
7. **禁止使用 NaN 作为比较哨兵**：涉及价差或指标比较时，严禁使用 `math.nan`（因为 NaN 的比较恒为 False 会导致下游风控静默穿透），必须使用 `Optional[Decimal]`。
8. **严禁使用占位符假收益**：非测试代码中严禁出现 `realized_pnl = 0.0 # TODO` 等伪实现；必须具备真实的成本基准核算实现（FIFO / 加权移动平均）。

### 3. 时钟、并发与资源安全
9. **严禁策略执行依赖 Wall-Clock 时间**：策略决策、冷却期、K 线滚动计算严禁直接调用系统当前时间（如 `datetime.now()`），必须统一由 `ClockProvider` 或行情 Tick 时间轴驱动，确保实盘、回测与重播 100% 确定性。
10. **禁止跨协程 await 持有阻塞同步锁**：在 `async` 异步函数中跨越 `await` 挂起点时，严禁持有 `threading.Lock` 等同步互斥锁，防止主事件循环死锁与线程饥饿。
11. **热路径极致避免堆分配与阻塞锁**：在毫秒级行情解析、指标更新等高频热路径上，优先采用预分配 Buffer 与轻量原子/无锁结构，严禁在热循环中频繁分配大内存对象。
12. **日志写入必须配置最大容量与轮转策略**：量化高频流生成海量日志，所有日志写入器必须配置最大单文件尺寸（如 100MB）与轮转保留数量，严禁无限制写入撑爆磁盘。
13. **并发资源检查与扣减必须原子化 (Anti-TOCTOU)**：限频检查、每日交易额度扣减等必须在单次原子锁内完成检查并扣减，严禁分离的“先查后改”。
14. **滑动窗口与循环队列容量限制**：滑动 K 线和盘口队列必须有显式容量上限（`maxlen`），严禁使用无界的内存集合导致长时间运行内存泄漏。

### 4. 研发真实性与证据链
15. **禁止无终端输出的假测试声明**：宣称“测试已通过”必须附带终端真实的原始执行输出，无真实输出的声明一律视为无效 (Void)。
16. **外部 API 必须前置版本静态核验**：调用任何第三方库或 SDK 前，必须先核验当前依赖版本中该方法确实存在，严禁凭借概率幻觉虚构不存在的函数名。
17. **禁止将伪造数据标为健康数据**：未连接实时行情时必须显式标记为离线/回退模式，严禁使用随机数/硬编码行情伪装成健康实时流。
18. **严禁代码伪实现占位符 (Stubs)**：生产路径中严禁提交 `pass`、`NotImplementedError` 或空函数作为交付物。
19. **未验证失败直接写出的业务代码一律物理删除**：TDD 必须遵循“先构造失败测试 $\to$ 验证失败 $\to$ 实现使之变绿”的闭环。

### 5. 架构边界、安全与 Schema
20. **严禁业务逻辑无节制堆砌到入口文件**：除 CLI 参数解析与生命周期信号分发外，所有核心逻辑必须按职责下沉到各功能子模块中。
21. **严禁新增隐式全局回调注册**：优先采用显式接口、依赖注入或事件总线机制，确保代码静态调用链清晰可查。
22. **Schema 迁移独占与幂等升级**：持久化数据库/文件结构变更必须具备独立的迁移脚本，支持快照、数据验证与回滚。
23. **KMS 私钥零明文落地与隔离**：私钥严禁以明文形式写入任何日志文件、环境转储或异常堆栈中；推荐外部签名器隔离。
24. **默认纸盘沙箱保护 (Paper First)**：未显式传入实盘认证和实盘开关时，系统撮合逻辑必须强制运行在纸盘（Paper）模拟模式。
25. **风控告警必须配置有效外发通道**：Warning 级别以上的风控警报必须具备外部通知机制（Webhook / Alertmanager），严禁仅打本地 Log 假装已告警。
26. **明确冰山单探测与冰山单发送的边界**：盘口冰山单特征识别（行情层）与拆单算法下单（执行层）必须严格物理隔离。
27. **修改高危热路径必须先评估爆炸半径**：在改动订单流、风控引擎与资金核心前，必须先理清逆向调用链（Callers）。
28. **跨平台兼容与路径规范**：文件路径拼接必须使用 `pathlib.Path` 或 `os.path`，严禁硬编码特定操作系统的斜杠分隔符。
29. **禁止在未定义信息架构前编写 UI**：前端页面和终端 UI 修改必须先明确信息层级和数据契约。
30. **禁止在迭代中途无序蔓延需求范围**：开发过程中发现的设计遗漏必须单开任务单，严禁临时夹带私货破坏当前测试边界。
31. **性能热路径重构必须附带基准测试**：针对指标计算引擎的修改必须运行 benchmark，严禁在无性能对比数据的情况下宣称“优化”。
32. **历史重大缺陷免疫强制遵循**：编码前必须通读 `PROJECT_BUGS_POSTMORTEM.md`，对历史发生过的并发、浮点与重放缺陷执行强制规则免疫。
